# 限制自助注册邮箱后缀

## 用户故事

- 作为本地工作台管理员，我希望只让常见可信邮箱后缀自助注册，而不是让任意邮箱都能创建账号。
- 作为维护多用户本机环境的人，我希望临时调整支持的邮箱后缀，而不是每次都改代码或改数据库。
- 作为准备开放注册入口的人，我希望不支持的邮箱被清楚拒绝，而不是等账号创建后再人工清理。

## 为什么需要

注册入口一旦开放，账号边界就不只取决于密码强度，还取决于谁能进来。只靠“开放注册 / 关闭注册”太粗，要么完全放开，要么完全关掉；管理员需要一条更细的线，把自助注册限制在认可的邮箱后缀里。

## 怎么解决

管理员在后台维护一份支持注册的邮箱后缀列表。用户注册时，系统先检查邮箱后缀是否在列表内；支持的邮箱继续走现有注册流程，不支持的邮箱直接收到明确提示。管理员显式清空列表时表示临时不限制邮箱后缀。

## 边界

- 只限制新用户自助注册，不影响已有用户登录。
- 不验证邮箱所有权，不发送验证码，也不检查邮箱服务商是否真实可达。
- 不处理企业 SSO、邀请注册、一次性邮箱检测或黑名单策略。
- 要完全关闭自助注册时，仍使用“关闭注册”开关。

## 2026-05-27 实现记录

- 后台系统设置已支持维护注册邮箱后缀支持列表，并在保存时统一转为小写、去重、去掉可选的 `@` 前缀。
- 新库和旧库升级默认使用 7 个邮箱后缀：`126.com`、`139.com`、`163.com`、`189.cn`、`aliyun.com`、`gmail.com`、`qq.com`。
- 用户自助注册时，系统先检查 `allowRegistration`，再检查邮箱后缀，最后才进入邮箱查重和用户创建流程。
- 管理员显式保存空白名单表示“不限制邮箱域名”；字段缺失、`NULL` 或坏 JSON 仍回退默认 7 项。
