# 优化后台兑换码页面与全站导航选中态

## 背景

后台兑换码页当前把创建表单、过期快捷按钮、生成按钮和列表直接塞进同一块区域。截图中可见问题：

- 兑换积分、生成数量、过期时间横向排布生硬，控件高度和视觉重量不统一。
- 快捷过期时间按钮像临时补丁，没有选中反馈，也没有和过期时间输入形成明确关系。
- 兑换码列表空状态占据大块区域，但缺少筛选、统计和下一步动作。
- 选中态使用纯黑背景，和项目既有“暖纸、深墨、铜色操作、青绿焦点”的视觉方向冲突。
- 页面整体像低完成度后台表单，不像可长期使用的运营工具。

用户已确认本任务范围扩展到顶部全站导航和语言切换：导航当前页面态、语言当前态和后台 tab 当前态都不能继续依赖纯黑选中块。

## 目标

把后台兑换码页优化成稳定、可扫读、有清晰操作层级的运营页面，同时统一顶部全站导航、语言切换和后台 tab 的选中态视觉。重点改善筛选/创建控制区布局、选中态颜色、按钮交互和空/加载/结果状态，保留现有兑换码业务能力。

## 已确认事实

- 页面实现位于 `apps/web/src/features/admin/AdminPage.tsx`。
- 兑换码页样式位于 `apps/web/src/styles/admin.css`。
- 顶部全站导航和语言切换由 `apps/web/src/features/canvas/CanvasApp.tsx` 的 `TopNavigation` 和 `LanguageSwitcher` 渲染。
- 顶部导航与语言切换浅色样式主要在 `apps/web/src/styles/layout.css` 和 `apps/web/src/styles/layout-theme.css`，深色覆盖在 `apps/web/src/styles/dark.css`。
- 现有兑换码接口一次读取 `/api/admin/redemption-codes?limit=200`，前端已按创建时间倒序排序。
- 当前共享契约包含 `RedemptionCodeSummary`、`RedemptionCodeStatus`，状态只有 `active` 和 `disabled`；已兑换和已过期需要从 `redeemedAt`、`redeemedByUserId`、`expiresAt` 派生。
- 项目设计文档要求沿用暖纸、深墨、铜色操作、青绿焦点，不引入通用 SaaS 蓝紫渐变或玻璃拟态。
- `ui-ux-pro-max` 已用于设计决策：采用数据密集运营后台、青绿色信任色、表单可见标签、导航 active 明确指示、可见焦点、hover 反馈、提交反馈和响应式检查。
- `ui-ux-pro-max` 的 OLED 暗黑、企业落地页、通用蓝色 CTA 建议与项目既有暖纸工作台方向冲突，本任务不采纳。

## 需求

- 重新组织兑换码页内容层级：标题说明、关键统计、筛选条、创建表单、最近生成结果、列表/空状态要各自清晰。
- 增加列表本地筛选能力，至少支持全部、可兑换、已停用、已兑换、未兑换、已过期，并支持按兑换码或兑换用户信息搜索。
- 筛选后列表、统计和空状态要一致：无数据和无匹配结果应显示不同文案，并提供清除筛选动作。
- 筛选按钮需要显示当前筛选状态，并可展示对应数量，避免用户点筛选后不知道当前数据范围。
- 创建表单要更像运营工具：积分、数量、过期时间和快捷过期按钮关系明确；生成按钮位置稳定；加载态和提交态不造成布局跳动。
- 快捷过期时间按钮需要有 selected 状态和 `aria-pressed`；手动修改过期时间后清除快捷按钮 selected 状态。
- 所有选中态不使用纯黑底。后台 tab、筛选按钮、快捷过期按钮和本次生成复制按钮应使用项目色板中的铜色、青绿色或暖纸变体。
- 顶部全站导航当前页选中态要同步优化：当前页要清晰可见，但不能像普通白底按钮或黑底按钮；图标和文字要有统一强调。
- 语言切换当前态要同步优化：中文/EN 选中按钮不能使用纯黑或强反白，浅色和深色主题下都要有足够对比。
- 设计决策：全站导航、语言切换、后台 tab 和兑换码筛选的 active/focus 主色统一使用青绿色体系；铜色保留给主操作、运营强调和少量边框细节。
- 顶部导航改动必须保持横向滚动、账号菜单、管理员入口和移动端压缩规则不退化。
- 保持所有可见文案走 `apps/web/src/shared/i18n/index.tsx` 的中英文翻译。
- 保持键盘可访问：表单控件有标签，筛选按钮有明确状态，焦点可见，点击目标至少 40px 高。
- 保持移动端可用：375px 宽度无横向滚动、无文字重叠，筛选和表单自然堆叠。
- 搜索要做大小写和空格规范化，至少匹配兑换码、兑换用户名称、邮箱和用户 ID。
- 已过期与可兑换判断要基于统一的当前时间快照，避免同一轮渲染内统计、筛选和行状态不一致。

## 不在本任务范围

- 不改兑换码 API、数据库结构或分页协议。
- 不实现服务端筛选、导出、批量禁用或高级审计。
- 不重做整个后台的所有页面，只同步后台 tab 选中态。
- 不重做顶部导航的信息架构、路由、品牌区、账号菜单或登录流程，只调整选中态、hover/focus 和必要的视觉一致性。

## 验收标准

- [ ] 兑换码页在桌面视口中形成清晰的“统计/筛选 + 创建 + 列表”布局，视觉不再像单个粗糙表单。
- [ ] 顶部全站导航、语言切换、后台 tab 和兑换码页内选中按钮不再使用纯黑底，选中、hover、focus、active 状态符合暖纸/铜色/青绿色体系。
- [ ] 用户可以通过本地筛选查看全部、可兑换、已停用、已兑换、未兑换、已过期兑换码，并可按兑换码或兑换用户搜索。
- [ ] 可兑换筛选内部命名不复用 API 的 `active`，避免把“状态 active”和“仍可兑换”混淆。
- [ ] 筛选无匹配时显示专门空状态，并能一键清除筛选；真实无兑换码时仍显示“还没有兑换码”语义。
- [ ] 创建兑换码表单保留现有校验、快捷过期时间、单码自动复制、多码展示和成功/失败提示能力。
- [ ] 快捷过期时间按钮有 selected、hover、focus、active 和清除逻辑，手动改日期后不会保留错误 selected 状态。
- [ ] 表格行操作复制、启用/停用、删除的交互和禁用态保持可理解，不因视觉调整改变业务规则。
- [ ] 全站导航当前页、语言当前项、后台当前 tab 在浅色和深色主题下都清晰可辨，并保持键盘焦点可见。
- [ ] 375px、768px、1024px、1440px 视口无明显重叠、截断或横向页面滚动。
- [ ] 完成实现后运行 `pnpm typecheck`、`pnpm build`，并用浏览器验证本地 Vite 页面。

## 已拍板决策

- 范围扩展到全站顶部导航和语言切换选中态。
